Run this path against a **self-run Limetry node**. Point the CLI at your local
API and use `LIMETRY_BEARER_TOKEN` (or scoped API tokens you issue on that node).

## Install the published toolchain

- Node.js ≥ 20 and a package manager you prefer
- A self-run Limetry node, or Limetry Cloud

For the CLI and MCP host, install the published packages:

```bash
npm install -g @limetry/cli
```

Use the package manager you prefer; the equivalent Yarn or pnpm commands work
the same way. To self-host the server, use the source checkout instructions in
[Run the server yourself](/docs/server/self-hosting).

<Steps>
<Step title="Start the server">

Set a bearer token (minimum 32 characters in production) and start the governance server:

```bash
export LIMETRY_BEARER_TOKEN="dev-local-bearer-token-min-32-chars"
node packages/server/dist/index.js
```

The API listens on `http://localhost:3810` by default.

**Docker alternative:**

```bash
docker build -f packages/server/Dockerfile -t limetry-server .
docker run -p 3810:3810 \
  -e LIMETRY_BEARER_TOKEN="dev-local-bearer-token-min-32-chars" \
  limetry-server
```

Verify health:

```bash
curl -s http://localhost:3810/health
```

</Step>

<Step title="Configure the CLI">

Point the CLI at your self-run server:

```bash
limetry setup
```

Enter `http://localhost:3810` and paste the same `LIMETRY_BEARER_TOKEN`.

Run doctor to confirm connectivity:

```bash
limetry doctor
```

</Step>

<Step title="Apply a policy">

Deny `http_post` to a production URL pattern (allow GET for contrast):

```bash
limetry policy apply \
  --allow http_get \
  --deny http_post \
  --block-resource "https://prod.example.com/*"
```

Prefer policies with `audit_mode: "minimal"` (slim builder default) unless you
need forensics retention of redacted metadata.

Record the `policy_id` printed in the JSON response. You need it for evaluation.

</Step>

<Step title="Evaluate an intent">

Pipe an `ActionIntent` JSON document to `limetry eval`:

```bash
echo '{
  "policy_id": "PASTE_POLICY_ID_HERE",
  "agent_id": "demo_agent",
  "action_type": "http_post",
  "resource": "https://prod.example.com/api/deploy"
}' | limetry eval
```

Expect **DENY** with reasons referencing the blocked resource or denied action type.

Evaluate an allowed GET to the same host (adjust policy if needed) to see **ALLOW**.

</Step>

<Step title="Tail the audit log">

```bash
limetry audit tail --event-type policy.evaluated
```

Look for `policy.evaluated` events with your agent id and decision outcome.
Stored events are **privacy-safe records** (default `audit_mode=minimal`) — not
raw metadata bags. Do not put API keys or chat transcripts in intent `metadata`
or record `details`. See [Minimize audit data](/docs/server/data-minimization).

</Step>
</Steps>

## Connect Cursor MCP (optional)

```json
{
  "mcpServers": {
    "limetry": {
      "command": "npx",
      "args": ["-y", "@limetry/mcp"],
      "env": {
        "LIMETRY_API_KEY": "dev-local-bearer-token-min-32-chars",
        "LIMETRY_BASE_URL": "http://localhost:3810"
      }
    }
  }
}
```

Available tools: `limetry_evaluate`, `limetry_record_action`, `limetry_list_audit`, `limetry_upsert_policy`.

Instruct Cursor to call `limetry_evaluate` before irreversible tool calls.

## Evaluate from the SDK

```typescript
import { RemotePolicyEngine } from "@limetry/sdk"

const engine = new RemotePolicyEngine({
  baseUrl: "http://localhost:3810",
  apiKey: process.env.LIMETRY_BEARER_TOKEN,
})

const decision = await engine.evaluateAction({
  policy_id: process.env.POLICY_ID!,
  agent_id: "demo_agent",
  action_type: "http_post",
  resource: "https://prod.example.com/api/deploy",
})

if (!decision.approved) {
  console.error("Denied:", decision.reasons)
}
```

<Warning>
Block the tool call in your agent loop when `approved` is false. The SDK does
not enforce deny for you.
</Warning>
